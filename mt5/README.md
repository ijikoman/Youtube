# MT5検証手順

現環境はLinuxで、MT5 / MetaEditor / Wineは未導入。EAは未コンパイル・未バックテスト。
このファイルは実行手順であり、実行結果ではない。架空の利益や取引を検証結果として使わない。

1. WindowsのMT5とMetaEditorを用意する。ブローカーのデモ口座から銘柄仕様・履歴を取得する。口座情報はリポジトリに保存しない。
2. `ResearchPullback.mq5` をMT5データフォルダーの `MQL5/Experts/Research/` にコピーする。
3. MetaEditorでコンパイルし、エラー・警告を確認する。ログを保存する。修正が必要なら検証前に直す。
4. ストラテジーテスターでEA、XAUUSD相当の銘柄、M5、「リアルティックに基づいた全ティック」を選択。最適化は無効にする。
5. 入金額・口座通貨・レバレッジ・約定遅延を固定。まず短期間をビジュアルモードで実行し、EMA・ATR・エントリー・SL/TPがルールに一致するか照合する。
6. `projects/gold-pullback/research.md` の開発期間と確認期間を別々に実行する。固定ロットのリスクが妥当か、証拠金不足や注文拒否も確認する。
7. 各回を別フォルダーに保存: テスターレポート、パラメーターのset、Journal、ブローカー仕様、開始終了日時、EAのソースコピー、使用データの状況。ティックが欠けている場合はその期間の結果を採用しない。
8. テスターエージェントの `MQL5/Files/research_deals_*.csv` を回収する。ログにファイル名が出る。ローカルAgentのデータフォルダーはMT5の構成により異なる。最適化・クラウドエージェントでの回収は対象外。
9. 取引CSVの実現損益（profit + commission + swap + fee）をレポートと突合する。CSVだけでは含み損を含む最大エクイティDDは算出できないため、必ずMT5レポートを使う。履歴で別建て請求される費用はCSVで欠落し得るので差異を確認する。
10. 実際の取引履歴をビジュアルモードで再現し、勝ち例・負け例を同じ選定基準で収録する。全取引の集計も示す。

結果として記録するもの: 純利益、リターン、最大残高DD・最大エクイティDD（額と率）、取引数、PF、勝率、平均損益、連敗、コスト、注文拒否。
利益が出ても将来利益の保証とはしない。取引数不足・期間依存なら判断保留。

## 使用するMT5の選定（ユーザー指定）

バックテスト中のMT5は使わず、空いているインスタンスを使用する。
Windows接続先が確認できたら、各terminal64.exeの実行パスと対応するデータフォルダーを特定する。
プロセス名やCPU使用率だけで空きを判断しない。対象ターミナルのテスター画面・Journalでテスト/最適化の実行有無を確認する。
実口座の自動売買に使用中、またはテスト状況が不明なインスタンスも選ばない。
既存のテストを停止したり、ターミナルを強制終了したり、口座・設定を上書きしない。
テスターエージェントの共有使用による競合も確認し、利用中のエージェントを奪わない。
空きが確認できた対象にだけEAを配置し、開始直前に状態を再確認する。
