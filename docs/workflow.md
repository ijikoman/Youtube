# 制作手順

## 企画単位の保存物

`projects/<企画名>/` に次を保存する。

- `research.md`: 一次資料URL、公開日、確認日、動画タイムスタンプ、確認できた発言・条件、未確認事項。
- `script.md`: 冒頭、人物・出典、手法、勝ち例、負け例、弱点、まとめ。CMは独立した節にする。
- `project.json`: シーン順、秒数、表示テキスト、ナレーション、画像・音声の相対パス。
- `assets/`: 自作チャート、使用許諾のある画像、収録音声。
- `licenses.md`: 素材の出所、ライセンス、必要な表記、許諾記録。
- `description.md`: YouTube概要欄、出典、広告表記、リスク説明。LINEのURLは確定するまでプレースホルダーにする。

## 調査から公開まで

1. 海外原動画・公式インタビューと大会主催者の結果を確認する。大会名、年、部門を記録する。
2. 本人が公開した条件、制作者の解釈、FX向けの追加条件を区別する。「日本初」や優位性を推測で断定しない。
3. 原動画の台詞や構成をそのまま翻訳するのではなく、出典を示して独自の解説を組み立てる。
4. 自作チャートには「説明用の仮想例」と記載する。実測結果を使う場合は期間、データ源、スプレッド、手数料などの条件を記載する。
5. 日本語音声を収録し、各シーンの尺に合わせる。CLIで検証・書き出し後、動画全体を目視・試聴する。
6. CMには「自社商品紹介」を表示する。本編の手法とEAのロジックが異なる場合は明示する。
7. 概要欄・LINE資料・価格・提供条件を確認したうえで手動公開する。

## LINE導線の設計メモ（未実装）

動画末尾 → 概要欄の公式LINE → キーワード送信 → 検証資料 → 商品説明・購入判断。
資料を準備し、実在するURLを確認してから動画に導線を載せる。
商品資料には取引条件、費用、損失例、最大ドローダウンと計測期間を記載する。
本プロジェクトはLINEへの送信や決済を行わない。
