## 3. 判断してほしいこと(売買ルールや検証条件に関わるため、ローカル側では変更していない)
1. **取引時間とデータの不一致。** 拒否された注文(開発178、確認151)は、すべてGMT 22:00〜23:05に集中している。コピーしたExnessの取引時間では休止の時間帯だが、データには値がある(夏時間の時期は、データ側の休止がGMT 21〜22時)。次のどれにするか決めてほしい。
   - (a) この時間帯は取引しないことをルールとして明記する
   - (b) カスタム銘柄の取引時間をデータに合わせる
   - (c) データのタイムゾーンを補正する
   (b)か(c)を選ぶと新しい試行になるので、別の記録として扱う。
2. **スプレッドが上限ちょうどのときの扱い。** `(ask-bid)/_Point > MaxSpreadPoints` を小数で計算しているため、スプレッドがちょうど800ptでも見送られることがある(確認期間で6件)。境界を含めるか、含めるなら誤差の扱いをどうするか。
3. **SL幅よりスプレッドが広い場合の見送り**(stops_level_skip、開発期間で7件)。このままでよいか。
4. **スワップ。** 過去の実際の値ではなく、現在の値で固定している。記載のみでよいか。
5. **データの提供元**はユーザーに確認中。動画や概要欄には「提供元未特定のGMT+0ティックデータ」と書くか、判明した名前を使う。
6. `projects/gold-pullback/research.md` と `result-template.md` に、この結果と未解決事項を反映する。

## 4. 動画用のチャート画像(ユーザーの希望:ティックから作ったOHLC画像を動画に埋め込む)
- 素材: `data/xauusd_gd/xauusd_gd_m5_202201_202512.parquet`
  - 列は time(足の開始時刻、GMT+0)、bid・askそれぞれのOHLC、ティック数、スプレッドの最小・平均・最大
  - bid OHLCは、MT5テスターのM5足28万本余りと完全一致を確認済み
- 取引: 各runの `research_deals_*.csv`
  - 時刻はGMT+0。entry: 0=新規、1=決済。type: 0=買い、1=売り。reason: 4=SL、5=TP
  - positionで新規と決済を結び付ける
- 勝ち例・負け例は、**選ぶ基準を先に決めて文書に残してから**選ぶ(例: 各期間の「中央値に近いTP決済1件とSL決済1件」など)。都合のよい例だけを選ばない。全取引の集計もあわせて示す。
- 描く内容:
  - ローソク足はbid
  - 買いの約定はask、売りの約定はbidで描く
  - EMA20/50、エントリー、SL、TP、決済の位置
  - 画面に「実測」「データ源」「期間」「条件」を表示し、「将来の利益を保証しない」と添える
- 出力は1920×1080で、`project.json` の `image` に入れられる形式にする。
- M1足やティック単位の拡大図が必要なら、使う取引の position ID と前後の時間幅をローカル側に依頼する。M1(45MB)と生ティック(5GB)はローカルにだけあり、必要な区間だけ書き出して渡す(`mt5/diagnostics/export_ohlc.py` を使う)。
