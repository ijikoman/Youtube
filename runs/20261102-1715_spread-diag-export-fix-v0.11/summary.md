## 2. 取引CSVの修正(`mt5/ResearchExport.mqh`)

方式:
1. symbolとmagicがEA自身のものである**新規約定**(IN / INOUT)から、DEAL_POSITION_IDを集める。
2. 同じsymbolで、そのポジションIDに属する約定を**決済側のmagicに関係なく**すべて出力する。
3. 約定チケットを並べ替えて重複を除外する。
4. 履歴の取得範囲は TimeCurrent()+366日まで。出力時点でまだ開いている自分のポジション数もログに残す。

CSVの列も追加した: time_msc、reason、magic、comment。

### ExportTest(専用のテストEA。同じ銘柄・ヘッジ口座)
| ポジション | 内容 | 期待 | 結果 |
|---|---|---|---|
| A(#2) | 自分のmagicで買い → 別magic 555で決済 | 2行出力 | deal 2・6を出力。6はmagic=555 |
| C(#5) | 自分のmagicで売り0.02 → 0.01を部分決済 → 残りはテスト終了時に強制決済 | 3行出力 | deal 5・8・9を出力。9は `end of test`、magic=0、reason=0 |
| F(#3) | 他magic 999で買い → 999で決済 | 出力しない | 出力なし(deal 3・7) |
| G(#4) | 他magic 999で売り → テスト終了時に強制決済 | 出力しない | 出力なし(deal 4・10) |

- 出力は5行で、重複0。レポートの総損益-57.94 = CSVの-31.66 + 他magic分の-26.28(+4.90と-31.18)。約定ごとの損益・スワップ・手数料はすべて一致した。

### 強制決済がOnDeinitの後に起きる可能性
- ログの順序: `position closed due end of test`(17:03:29.736)→ OnDeinitでの出力(.738)。テストBでも同じ順序だった。
- 出力時点で開いていた自分のポジション: ExportTest、A、Bのいずれも **0**。
- 少なくともこのビルド(6230)のテスターでは、強制決済はOnDeinitより前に履歴へ入る。ほかのビルドやケースのために、出力時点の未決済数を毎回ログに残す。

### テストB(v0.11、MaxSpreadPoints=1000)での確認
- CSVは106行(重複なし)、レポートは106約定。約定ごとの差異0、レポートにだけある約定0。
- **終了時の強制決済 deal #107(+8.93、`end of test`)がCSVに入った。**
- **総損益: レポート -43.09 = CSV -43.09**(v0.10では-52.02で、8.93の差があった)。

### v0.10との取引一致
- v0.10のBのCSV(105行)とv0.11のBの最初の105行を比べた。約定番号・ポジション・時刻・売買方向・価格・損益・スワップがすべて一致した。
- 増えたのは #107(end of test)の1行だけ。売買の挙動は変わっていない。

## 変更記録(ResearchPullback v0.10 → v0.11)
| 変更 | 理由 | 売買への影響 |
|---|---|---|
| `#include "ResearchExport.mqh"`。OnDeinitのCSV出力をこれに置き換えた | magicでの絞り込みにより終了時の強制決済などが漏れていたため | なし(OnDeinitでのみ実行) |
| 診断用のカウンター、スプレッドの分布、見送りログを追加 | 取引0件の根拠を数値で示すため | なし(値は判定に使わない) |
| 売買条件2行(buy/sell)をスプレッド判定の前へ移した。条件式は同一 | 見送った足の中で売買条件の成立を数えるため | なし(どちらの順でも、スプレッド超過なら発注しない) |
| version 0.10 → 0.11 | レポートやログで区別するため | なし |

注意: 新しい版は `ResearchPullback.mq5` と `ResearchExport.mqh` を同じフォルダーに置いてコンパイルする必要がある。
